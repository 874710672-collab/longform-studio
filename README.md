# 长篇工坊 · Longform Studio

把一部 35-40 万字的长篇，拆成 **30-36 个短篇单元**逐个生产。
每个单元都按短篇标准写完整（有钩子、有冲突、有爆点、有收束），靠**交棒单**把单元咬合成一本书。

> 核心判断：生成质量由「单个单元有多完整」决定，连续性由「单元之间的接口有多明确」决定。

---

## 在 iPad 上用（推荐）

1. 用 Safari 打开：**https://874710672-collab.github.io/longform-studio/**
2. 点底部「分享」→「添加到主屏幕」
3. 从主屏打开，第一次点右上角 ⚙︎ 填 Base URL / API Key / 模型

配置与你的「短篇工坊」共用同一份 localStorage 键位，但两套应用数据互相独立，不会串。

## 流程

```
【全书层】只做一次
  1 全书总纲      主线 / 主角弧光 / 反派动机 / 世界规则 / 结尾落点
  2 人物总表      结构化，点一下进硬事实表（性别、说话方式是硬约束）
  3 主线推进表    把主线切成 N 格，每格写「推进了什么 / 谁改变 / 不许碰 / 规模 / beat 数」
        ↓ 通过后自动建出单元列表
【单元层】每个单元 6 道工序
  1 单元立意      带全书总纲 + 本格要求 + 上一篇交棒单 + 硬事实表 + 待收伏笔
  2 出场配置      增量式：已有人物只读，新人物追加
  3 分节大纲      单节 ≤4000 字（太长会被截断）
  4 分节正文      一节一次调用
  5 润色成稿      按节分段润色
  6 交棒单        定稿后强制产出，喂给下一篇
```

---

## 三张表保证连续性

| 表 | 作用 | 谁维护 |
|---|---|---|
| **硬事实表** | 人物（姓名/性别/年龄/说话方式）、世界规则、关键物品、时间锚点 | 只增不改；人物总表和出场配置写入 |
| **伏笔表** | 编号、描述、埋于第几篇、计划第几篇回收、状态 | 交棒单写完自动入库/销账 |
| **交棒单** | 时间地点、状态变化、新埋伏笔、回收伏笔、**下一单元必须接住的（≤3 条）**、开场画面 | 每个单元定稿后生成 |

**交棒单是整套流程最关键的一份文档**。下一篇生成时，上下文里带的是「硬事实表 + 本格要求 + 上一篇交棒单 + 各单元一句话摘要 + 未回收伏笔」，总量控制在 5000 字以内，**不随书长增长**。

## 防止灌水 / 防止过密

每个单元先定 **beat 数**（要覆盖几个关键事件），程序按 `beats × 1500~2000 字` 反推合理字数区间，再和档位比对：

| 情况 | 判定 | 提示 |
|---|---|---|
| beats×2000 > 档上限 | 内容太密 | 升档，或拆成两个单元 |
| beats×1500 < 档下限 | 撑不住 | 降档，或与相邻单元合并 |
| 区间重叠 | 合理 | 通过 |

这是**机械校验**，不依赖模型自觉。单元列表上直接标红/黄徽章，「容量体检」能看全书总字数偏差。

### 篇幅档位

| 档 | 字数 | 节数 | 建议 beat |
|---|---|---|---|
| 小 | 3000-5000 | 3 | 2-3 |
| 中 | 8000-12000 | 5 | 4-7 |
| 大 | 15000-20000 | 7 | 8-12 |

35-40 万字建议：8 小 + 18 中 + 8 大 = 34 个单元 ≈ 35.2 万字（留余量到 40 万）。

## 改结构（三层随时可改）

**改档位** —— 选「只改字数」或「按新档重排大纲」（节数会变）

**改单元数** —— 合并相邻两篇 / 拆分一篇 / 插入 / 删除

**改边界** —— 合并后原文保留在合并记录里，可撤回

### 重跑规则

改动后按依赖闭包标记：**被改动的单元 + 其后所有主线单元** → `stale`（列表里标灰）。

但因为 `relayIn` 会取「最近一个未 stale 且已定稿的单元」的交棒单，**从中间重跑不需要从头来**。

每次结构改动写一条历史记录，可回到上一个结构快照。正文不删，只改结构引用。

---

## 副线单元（方案 B）

- 6-8 个，插在主线单元之间
- 视角：反派 / 盟友 / 旁观者，**不含主角**
- **不占主线格子**，但必须推进「读者比主角多知道的事」
- 不写主线交棒单，只记录读者知识
- 完全独立生产，写崩了重跑不影响任何主线内容

---

## 章节由人工标注

**程序不管章节**。单元是唯一存储单元，`chapterLabel` 只是显示层。
好处：随时可以重切，不影响内容。导出时按人工标注的章节号输出。

---

## 导出

- 正文全文（含未定稿）
- 只导定稿
- 大纲合集
- 交棒单合集
- 整本书数据（JSON 备份，建议定期导一次）

---

## 建议的使用节奏

**先只跑 3 个单元。** 如果这 3 篇读起来像一篇连续的作品，结构就成立；如果像 3 篇独立文章，说明交棒单约束写得太虚——回去改交棒单模板的约束强度，别急着往下跑。

跑通后再批量。每完成 5 个单元统计一次实际字数均值，偏差超过 10% 就重新分配后续档位。

## 已知限制

- 数据存在浏览器 localStorage，**换设备不自动同步**。定期用「导出 → 整本书数据」备份。
- 清缓存/换浏览器会丢数据。建议同时用「添加到主屏幕」，PWA 的数据更稳。
- 没有配置 API Key 时所有生成按钮都会提示去设置页。
- 单次输出上限建议 ≥32000 tokens，否则长节会被截断（程序会提示）。
